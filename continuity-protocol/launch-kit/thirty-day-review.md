# CPS-0001 v1.0-RC1 — 30-Day Community Review

## 状态

- **开始日期**: 2026-08-29
- **结束日期**: 2026-09-28
- **当前阶段**: Week 1 — Observation

## 观察指标

### Primary Metrics（最有价值）

- [ ] Independent implementations — 有人实现了我们没有写的 producer 或 verifier
- [ ] Technical criticism — 有人发现协议的真实缺陷
- [ ] GitHub issues / discussions — 实质性的技术讨论
- [ ] External references / citations — 有人在他们的作品中引用 CPS-0001

### Secondary Metrics（有则更好）

- [ ] GitHub stars — 兴趣指标，非验证
- [ ] Social media engagement — 点赞、分享、评论
- [ ] Press mentions — 文章或博客提及

### 我们不追求的

- 社交媒体浏览量
- 关注者数量
- "Hype" 或 "buzz"
- 表面互动

## Review 原则

1. **RC1 is frozen.** 在 review 期间不改变协议语义。
2. **All criticism is welcome.** 即使是"这个协议没有价值"也是有价值的反馈。
3. **No marketing spin.** 诚实面对限制。
4. **GitHub is the source of truth.** 所有平台指向 GitHub。
5. **Quality over quantity.** 一个独立实现比 10,000 个赞更有价值。

## Week 1: Observation（Day 1-7）

- [ ] 每日监控 GitHub issues 和 discussions
- [ ] 24 小时内回复所有实质性评论
- [ ] 不辩护协议 — 倾听并记录
- [ ] 在运行文档中跟踪所有批评

## Week 2: Engagement（Day 8-14）

- [ ] 跟进有前景的线索
- [ ] 联系提出好问题的人
- [ ] 主动帮助独立实现者
- [ ] 记录反馈中的模式

## Week 3: Synthesis（Day 15-21）

- [ ] 将所有反馈编译为结构化文档
- [ ] 分类：bugs, design issues, missing features, unclear language
- [ ] 按严重性和频率排序
- [ ] 开始起草 v1.0 final 或 v1.0-RC2 变更

## Week 4: Decision（Day 22-30）

- [ ] 决定：v1.0 final, v1.0-RC2, 或重大修订
- [ ] 发布决定和理由
- [ ] 感谢所有贡献者
- [ ] 规划下一步
