# Discovery Questionnaire — Data Handling

Governance record for the public research questionnaire at
`/lab/discovery-survey` (table `discovery_survey`).

## What this questionnaire is

A research questionnaire. It collects answers to a fixed set of questions so the
answers can be analysed.

Submitting it does **not**:

- register you for anything,
- enroll you in any research programme,
- apply to recruitment or a cohort,
- enroll you in EV-000 or any other study,
- create an account, a participant ID, or a membership.

The questionnaire is separate from recruitment (`recruitment_applications`) and
from calibration sessions (`research_sessions`). There is no link between them in
the schema or the code, and none should be introduced.

## Consent

Consent is recorded, not assumed.

| Field | Meaning |
|---|---|
| `consent_at` | Server-generated timestamp of consent acceptance |
| `consent_version` | Identifier of the consent wording accepted (currently `survey-consent-v1`) |

- `consent_at` is generated by the server when the submission is accepted. A
  client cannot supply it — the API rejects any request that tries.
- `consent_version` must name wording the server supports. An unrecognised value
  is refused rather than stored.
- Consent wording is versioned. The stored value is what proves which text a
  respondent agreed to. Changing the wording requires a new version.

### Historical rows

Rows submitted before the consent step existed have `consent_at IS NULL` and
`consent_version IS NULL`. This is intentional.

- `created_at` is **not** used as a consent timestamp.
- No default is applied, because a default would fabricate a consent record for
  responses that were submitted before any consent step existed.
- A `NULL` consent means: *submitted before the consent step was introduced;
  whether consent was obtained at the time cannot be proven.*

### Known limitation

`discovery_survey` has an `allow_anon_insert` policy with `WITH CHECK (true)`,
which permits an unconstrained direct insert. A caller holding the public anon
key can therefore write a row without going through the API, and such a row will
have no `consent_at`. Application-level consent enforcement is not a complete
guarantee until that policy is addressed. This is tracked separately as a
security issue and is deliberately out of scope for the governance change.

## Contact

`contact` is an **optional follow-up contact**.

- Optional, up to 300 characters, trimmed; a blank value is stored as `NULL`.
- No email-format requirement — the field accepts email, WeChat, or a DM handle.
- It is used only to contact you about this questionnaire.
- It is not a participant ID, registration, enrollment, membership, or EV-000
  signup.
- Leaving it blank does not prevent your answers from being recorded; it only
  means we cannot contact you about them.

## Retention

**Responses are retained for 180 days from submission, then deleted according to
the questionnaire's data-handling policy.**

This 180-day window is a project governance decision for the current research
phase. It is a project policy — not a scientific standard, and not a legal
requirement.

No automated deletion job is implemented. The policy and the audit fields are in
place; enforcing the window automatically is separate follow-up work.

## Withdrawal

There is no self-service deletion portal. Requests are handled manually by email.

Contact: **protocol@myshape.com**

Please state which of the two you mean — they are different requests:

### Stop future contact

We stop contacting you about this questionnaire. Your response is retained under
the retention policy above.

### Request deletion of an existing questionnaire response

We locate the response and delete it. This cannot be undone.

### What to include

To help us locate the response, include whatever you have:

- the contact details you entered on the form, if you entered any;
- an approximate submission time;
- any answers you remember giving.

Contact details make a response easier to locate and verify, but they are not a
technical precondition for a deletion request. A request can still be made
without them.
